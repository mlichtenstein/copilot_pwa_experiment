How the lighting strategies work

Visibility polygons: threshold each cloud field and extract its boundary edges. Project these edges and the sun into the camera plane. Cast rays just beside each endpoint, stopping at the nearest edge, then connect the hits into a lit polygon. A pixel is lit by a group of layers only when it is inside every layer’s visibility polygon.

Front to back, the render order is: all-three light region → near cloud → middle-and-far light region → middle cloud → far-only light region → far cloud → sun/sky. The implementation composites this list in reverse. A translucent haze layer colors each lit region, including foreground air in front of the nearest cloud.

This is a screen-space point-light approximation, not a 3D shadow volume. Cloud-edge portions within sourceRadius of the projected sun are transparent to the light. Rays can escape a nearby cloud edge and continue outward, while more distant clouds still block them. If a cloud remains solid beyond the radius, the lit region stops at the radius in that direction. The circle is a pass-through zone, not a larger sun disk; 0 restores the original hard-blocked behavior. The default radius is 6 pixels on the 128×80 image, and it is disabled in geometric mode. Visibility polygons are clipped by an expanded screen boundary. CloudSharpness and cloudOpacity use the same silhouette threshold as the geometric mode.

Geometric shadows: the preceding experiment remains available unchanged below.

Three fixed cloud pictures sit at depths 22, 50 and 78, with 32×20, 64×40 and 96×60 cells. The camera has fixed 58° perspective. Each cell spans 4 world units.

For the air between each pair of layers, opaque cloud cells farther toward the sun are extruded away from it. These rectangular shadow prisms extend across the whole gap. Perspective makes their projected boundaries change width with distance.

shadowDensity = clamp((density − 0.35) × cloudSharpness + 0.35, 0, 2)
opaque = cloudOpacity × shadowDensity ≥ 0.5

For each screen position, intersect the camera ray with the prisms, merge overlapping shadow intervals, then integrate only the illuminated air between them. There is no stack of depth slices and no stepping through a 3D volume.

airLight(a, b) = exp(−haze × 0.04 × (a − gapNear)) − exp(−haze × 0.04 × (b − gapNear))

Sum this contribution over unshadowed depth intervals and tint with the approximate sunset color. Blend far cloud, illuminated air, middle cloud, illuminated air and near cloud. Two 64×40 screen buffers store the final gap colors; they represent the full depth of each gap, not midpoint samples.

Shadow edges stay crisp, using one camera ray per pixel. Cloud surfaces retain their prior soft, partially transmitting shading; their geometric air shadows deliberately use hard silhouettes. This is an artistic hybrid, not full physical transport. There is no multiple scattering, evolving density or illuminated foreground air ahead of the nearest layer.

Only the sun moves during playback. Pattern buttons change one cloud field at a time; reset restores the original patterns and lighting while keeping your selected strategy.
