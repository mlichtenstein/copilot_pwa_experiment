# Cloud simulator

Open the folder (its `index.html`) through an HTTP server, or use the PR's Review deployments link. `index.html` is the front page ("Eight small skies"): the shared header, a short welcome (why the site exists and how ratings help), 🎲 Random and ❤️ Random, a card per experiment (a still in `thumbs/`, its one line and a link) and a short guide to the common panel, hold for help, the ratings and 🔗 links. The app's start URL, installs and links to the folder land there, and every page links to the others. The app is a standalone PWA with relative paths and scope-isolated offline caching. (The first experiment, a threshold-cascade rain study, was removed once Noise weather did rain better.)

**Seeds are incidental.** In every experiment, no specific seed is meant to matter: behavior should look alike on any seed, and a result that only shows up on a hand-picked seed is a bug. Seeds exist only so a run can be reproduced and tested. Tests should check several seeds drawn at random rather than favorites; the model tests pin such a list in `core/test-seeds.js` so every run checks the same cases (`FUZZ_SEEDS=1` draws fresh ones, `FUZZ_SEEDS=123,456` runs those). Do not expose numeric seed entry fields: offer fresh weather/shape buttons instead. Keep seeds internal for repeatable tests and saved links, and make generation work across seeds.

## Exploring

- **The picture comes first.** On every page the canvas takes the whole left side at the largest size that fits under the rating bar, scaled with crisp pixels and its own aspect ratio; the title, playback and sliders scroll in a side column. On a narrow phone the canvas spans the width (at most 60% of the screen height) and the controls scroll below it.
- **Labels are code names.** Every slider, menu, radio group and toggle is labelled with its parameter key in `<code>` (`timeOfDay`, `driftSpeed`, `textureA`, `view`), and the common buttons' words match their ids; hold a control for its explanation. See [Control labels are code names](../../CODING_STANDARDS.md#control-labels-are-code-names).
- The rating bar above the canvas ([shared rating bar](../shared/README.md)) saves how the current settings feel; its **About** explains the emojis and 🔗 Copy link.
- Reduced-motion users start paused. Background tabs do not accumulate simulation catch-up.

## Files

Each experiment is a page, a UI script and a browser-independent model (for example `noise.html`, `noise.js`, `noise-model.js`), with tests beside the models.

The experiments are being moved onto one shared module architecture ([#68](https://github.com/mlichtenstein/copilot_pwa_experiment/issues/68)); Sunset study is the first. A ported experiment is a module (`sunset-experiment.js`) that describes its parameters as a schema and creates an instance with `update(params)`, `step(dt, frame)`, `render(frame)` → RGBA pixels and `dispose()`. `core/` holds the shared parts:

- `core/experiment.js`: the contract, parameter kinds (range, select as a menu or radios, toggle, seed, size for a grid-size switch; any of them grouped into a fieldset, greyed out by an `enabled` rule or hidden but saved), validation and cleaning of untrusted values. Experiments declare capabilities and the host decides what to show: `sun` (the Sun group; `legacySunShape: false` on pages that only followed the sun later, so their old links load on the default path), `seed` (which seed the common New seed changes), `stepSeconds` (how far Step moves the clock; one simulation tick). Other optional, generic capabilities: autoplay, buttons only that experiment has (`actions`, each with hold-to-see help), an old-format converter for ratings and links (`migrate`), text readouts, linked params (`adjust`), custom decorations (`decorate`), a status line (`stats`) and async loading (`ready`).
- `core/sun-path.js`: the one sun path every experiment with a sun follows, a vertical figure-eight (a 2:1 Lissajous loop, like an analemma) over a 90 s period: azimuth `sunPathX + sunPathWidth/2 × sin(4πφ)`, elevation `sunPathY + sunPathHeight/2 × sin(2πφ)`, where φ is the phase (0 to 1). The top lobe (φ 0 to 0.5) is above the crossing point (`sunPathX`, `sunPathY`) and the bottom lobe below it, so the sun mostly rises and sets with a small side-to-side swing. The four shape settings are shared host sliders on every sun page and saved with every rating; defaults are width 30°, height 46°, X 0°, Y 5°, so the sun spans 15° left to 15° right and 18° below to 28° above the horizon, deep enough for a real night. Each experiment maps those degrees onto its own picture. **Time of day**: the phase is shown as a 24-hour clock, `(6 + 24φ) mod 24` hours, so 06:00 is φ 0, noon (the top of the path, the sun highest) is φ 0.25, 18:00 is φ 0.5 and midnight (the bottom, the sun lowest) is φ 0.75; a day is still 90 s of Play, and pages start at 09:00. Ratings and links still save the phase as `sunPhase`, so they show the same sun; ones saved before the path had settings (no `sunPath*` keys, including old fixed-angle links) load the old shape, height 32° and Y 9°, so the default change does not move their sun.
- `core/sun-light.js`: how the shared sun lights a picture not drawn from 3D geometry (Convection's and Noise's Sunset views, Valley). `sunLight(sun)` gives the light's screen direction (from the right when the sun is 15° or more to the right, from the left likewise, from the front when it is ahead; from below while it is under 30° up, as the clouds sit high, from above higher), its `strength` (fading from +4° to −6°) and `day` (0 to 1 from 35° to 60° up: colours move from the warm low-sun palettes to daylight ones). On the default path the sun never passes 28°, so those pages stay warm all day, lit from the lower right in the morning, the front at noon and the lower left in the afternoon. Each model still draws the fixed low sun at the lower right it had before when called without a light (`BAKED_LIGHT`), which its tests use.
- `core/daylight.js`: night on every page. `daylight(elevation)` is 1 at and above +6° (daytime frames are untouched), a smooth (smootherstep) monotonic ramp through twilight, and 0 at and below −12°. After each render the host darkens a copy of the frame for that light toward a dim blue night floor (`applyNight`: at full night a pixel keeps 20% of its brightness over the colour rgb(5, 9, 24)), so night is dark blue, not black, and clouds stay faintly visible. Pages with `sun` shade their own dusk, so for them the ramp starts at the horizon (0°), only the floor is added below it, and a pixel keeps 30% (`NIGHT.sunKeep`), since their models have already dimmed; every page's night ends up about equally dark. Lightning has no sun of its own; it takes the same tint from the shared clock's sun on the default path. An instance may report `selfLight()` (0 to 1) for light it makes itself: Lightning returns its flash power, so a flash lights its frame back to full at night and the dark returns as it fades.
- `core/clock.js`: the shared clock (play/pause, frame steps capped at 250 ms, nothing while the tab is hidden) and the animation loop.
- `core/host.js`: builds the page from the schema, runs the loop, and connects the rating bar and `?p=` links (`getParams`/`applyParams`). Every page gets the same **common panel** at the top of its controls, with the same order, labels and texts, in compact rows (about 130 px tall without the Sun group at 1280 px wide):
  1. One row of buttons: Play/Pause and Step (one shared clock moves everything time-based on the page: sun, wind, simulation, lightning and Drift; Step pauses and moves the clock on one step, `stepSeconds`: one simulation tick, or one second), Randomize, and New seed, only on experiments that declare `seed`.
  2. One row with Drift and its Drift speed slider (below).
  3. The Sun group, only on experiments with `sun`: Reset sun (back to 09:00) and the shared time-of-day slider (`timeOfDay`, 00:00 to 24:00, shown as `HH:MM · N° up`; moving it pauses the clock) on one row, and the four `sunPath*` shape sliders folded in a closed "Sun path shape" disclosure. Pages without `sun` get the same time-of-day slider on its own row after Drift (shown as `HH:MM`), since night reaches every page.
  4. **Randomize** sets every setting of the experiment to a random value: every slider (greyed-out ones too, and Convection's `water`), every menu and radio (Valley's textures and horizon, Shafts' strategy, Convection's layering, views...), every toggle and every seed (Valley's brush layout, Shafts' patterns), plus a random time of day and, on sun pages, a random sun path shape. Menus and toggles are picked first and linked (`adjust`), then the values that depend on them. It leaves Play/Pause, Drift and Drift speed, and grid-size switches (`kind: "size"`, Convection's resolution) alone, and any param marked `randomize: false`: Convection's `speed` (a playback rate) and Lightning's hidden `start` (its own buttons choose the starting mode). Its random numbers come from the `random` option of `mountExperiment` (tests pass a seeded one).
  5. **Weather states**, only on experiments that declare `weatherStates`: a row after Drift, `weatherStates` then one button per named, checked-in state labelled with its code name. Weather layers has `thunderstorm` (dense, dark, high cloud on every layer, heavy rain, `storminess` .5 and `chargeBias` .4 at 18:15), where the first strike comes within a second or two and strikes keep coming. A jump sets every setting to the state's (`weatherStateParams`: defaults plus its values, fresh seeds; `randomize: false` settings and the grid size stay) and its time of day, leaving Play/Pause, Drift and Drift speed alone, so Drift may wander away again. Ratings and `?p=` links save the resulting settings, like any others.
- `core/header.js`: the header every page shows, built from `core/registry.js`: the site name, the page title and tagline, and a nav linking every experiment (Lightning included) in registry order with the same labels everywhere and the current page marked, not linked. The lines are fixed (title on one line, tagline clamped to two), so the header is the same height on every page and the panel lines up from page to page. Pages ship an empty `<header id="header">`. Its top row also holds 🎲 Random and ❤️ Random (`launchButtons`, hidden on the front page, which shows them large).
- `core/launch.js`: where those buttons go, and what carries over. 🎲 Random opens a random experiment with `?random=1`; that page randomizes every setting like Randomize, then drops the flag from the address. ❤️ Random reads the shared ratings (`listRated` in `../shared/presets.js`, read-only) for a random ❤️ on any experiment and opens it with its `?p=` settings; with no ❤️ yet, or no network, it says so under the buttons and stays put. **One sky:** leaving a page (a header link, or `pagehide`) saves `timeOfDay`'s `sunPhase`, the four sun path sliders, `drift` and `driftSpeed` to `sessionStorage`; the next page starts from them. A `?p=` link wins over the carry, and so does a ❤️ that has its own sun. 🎲 Random keeps a carried sun and Drift and randomizes the rest; arriving fresh, it randomizes the sun too.
- `home.js`: builds the front page from `core/registry.js` (cards, big launch buttons) and registers the service worker.
- `core/hold-help.js`: **hold to see**. Every description, in the common panel and in each experiment's own controls, is hidden (a `small.help` the control names in `aria-describedby`). Press and hold a control for about 400 ms, by touch or mouse, and it shows in one small popover beside it; release, a tap elsewhere or Escape hides it. With a mouse, resting on a control shows it too, and so does keyboard focus. Holding a button shows its help without pressing it (the click that ends the hold is swallowed); a short press is a normal click. A slider, menu or number box never starts a hold when you press the input itself, so dragging and typing are unchanged; hold its name or value instead. A press that moves more than 8 px (a scroll or drag) is not a hold. Keys with help have a dotted underline, and the panel heading says "ⓘ hold for help".

  Below it, under the experiment's own heading (for example "Lightning settings"), come its status line, its unique buttons and its own sliders, menus and toggles. Experiments never build common controls; Play labels such as "Play sun" or "Play wind" are gone (`playLabels` is rejected by validation). The emoji rating bar stays above the picture, where it is the same on every page.
- Drift, on every experiment page: a checkbox in the common panel, on by default on a fresh page load, that, while playing, moves each slider on its own slow Gaussian random walk (`../shared/drift.js`, `DRIFT.rate` 0.05: at 1× speed it typically moves 0.05 × √t of the slider's range in t seconds of clock time, about a fifth in 16 s, half in 100 s and the whole range in about 7 minutes). There is no pull back toward where a slider was last set, so it can roam its whole range; it bounces off the ends, its only limits, so values stay valid. A Drift speed slider beside it scales the step from 0.1× to 10× (log scale, 1× in the middle, saved as `driftSpeed`; links without it load 1×); it never drifts or gets randomized and stays live while Drift is off. Randomize, just above it, replaced each page's Reset button (see 4 above). Drift runs on the shared clock, so it stops when paused; dragging a slider takes that one over, and greyed-out sliders hold still. It moves only ranges that are not `drift: false` or hidden, so the sun, its four path sliders, playback speeds (Convection `speed`) and Convection's `water` (which restarts the run) stay put, as do seeds, choices and toggles. Its own random numbers leave simulation seeds alone. Ratings and `?p=` links save it as `drift` and load it as saved, on or off; links and ratings from before it (no `drift` key) load with it off, so a look saved then reproduces. Since it only moves while playing, it has no visible effect until Play on the pages that open paused (Sunset, Horizon, Shafts, Valley, Lightning); Convection and Noise open playing (unless reduced motion is set), so their sliders start wandering at once. An experiment can leave it out with `drift: false`.
- `core/registry.js`: the list of ported experiments. `manifest.json` describes installation metadata, uses relative start/scope URLs, and depends on `icon.svg`. `cloud-sw.js` precaches every runtime asset (front page and thumbnails included) in a cache named for its registration scope; `sw.test.js` follows every page's imports and fails if one is missing from the list.

## Experiment 02: sunset study

Open [sunset.html](sunset.html). Droplet density is fixed, seeded Gaussian patches extruded along camera depth into a 2.5D slab. `sunset-model.js` owns density generation and all lighting; `sunset-experiment.js` describes the parameters and wires the model into the shared host, and `sunset.js` only mounts it. The only animation is the distant sun moving along the shared vertical figure-eight path (`sunPhase` and the `sunPath*` shape; 45° of azimuth spans the half-width of the picture, and daylight follows the sine of the elevation); playback starts paused. Older saved settings with the previous `sunAngle` load everything except the sun's place. Manual sun positioning, repeatable density seeds, parameter descriptions and collapsed formulas support experimentation. Density, sunlight transmission and camera transmission views isolate the terms.

Beer–Lambert attenuation and Henyey–Greenstein single scattering follow the ideas in [PBRT transmittance](https://www.pbr-book.org/4ed/Volume_Scattering/Transmittance) and [phase functions](https://www.pbr-book.org/4ed/Volume_Scattering/Phase_Functions). Our cosine convention uses propagation directions (forward is +1). RGB atmospheric extinction, sky backdrop, neutral ambient fill, fixed solar depth direction and horizon fading are deliberate approximations. The finite slab has open lateral edges; rays outside the density grid see vacuum. Six depth samples and eight sun-path samples approximate the integrals; dense settings can show quadrature error. No multiple scattering or calibrated meteorology is claimed.

`extinction` is per density unit per pixel length, `slabDepth` is in pixel lengths; remaining radiometric quantities use relative units. Neither rain state nor density evolves in this experiment. The shared cloud service worker precaches sunset assets in the existing app scope; installation opens Noise weather, which links to Sunset study.

Run `node --test apps/cloud-simulator/*test.js apps/cloud-simulator/core/*test.js` for all experiments. Browser review: compare density before/after sun playback; watch the sun trace the vertical figure-eight and dip under the horizon in its bottom lobe; resize and move the path; scrub the sun toward the horizon; vary extinction/albedo/exposure and compare diagnostic views; check phone-width labels, pause/Randomize/new seed, and offline reload of both pages after worker activation. Browser verification must be recorded separately from model checks.

All experiment pages keep the field in a separate visible pane while controls and formulas scroll independently. Wide screens use side-by-side panes; phones stack the field above the controls. The controls region can receive keyboard focus for scrolling.

## Experiment 03: convection study

Open [convection.html](convection.html). A closed box (64 × 48 pixels by default, or 128 × 96; see Resolution below) of moist air is heated at the floor and cooled at the lid. `convection-model.js` owns the rules and the pixel colors; `convection-experiment.js` wraps it as an experiment module (view, Options, rule sliders, `speed` ticks per clock second, Step) and `convection.js` mounts it with `core/host.js`, which builds the controls, rebuilds on a resolution switch and wires the rating bar. Its Sunset view is lit by the shared sun (`core/sun-light.js`, see above), so the page has the Sun group; it keeps playing when a saved look loads, and saved runs also keep `speed`. Each pixel holds temperature, vapor, cloud, rain and vorticity; each floor column also holds a puddle.

Per tick: the floor relaxes toward a hot temperature with a random per-column flicker, the lid toward cold. Puddles evaporate into the floor row. Vapor above an altitude-dependent capacity condenses and releases latent heat; cloud and rain in subsaturated air evaporate and cool. Cloud above 0.005 per pixel gathers into rain at `autoconversion` per tick. Sideways differences in `temperature − 0.4 × (cloud + rain)` spin the air (a 2D Boussinesq vorticity rule with drag and viscosity). A stream-function solve turns spin into divergence-free edge flows, capped at 0.24 pixels per tick at 128 × 96. Heat, water and spin move by conservative upwind fluxes. Rain falls one pixel per tick at 128 × 96 at the default `fallSpeed` of 1 (half a pixel at 64 × 48, the same speed across the box), outrunning the strongest updraft, so it comes down in shafts; rain reaching the floor refills the puddles.

The feedback loop keeps it going: warm floor air rises and condenses, latent heat makes the cloud more buoyant, the lid cools it, rain falls out and evaporative cooling below drives downdrafts, and the puddles re-wet the floor. Nothing drains, so vapor + cloud + rain + puddles is conserved up to floating-point rounding. The flicker stops the flow from locking into steady rolls. The page picks a random seed; New seed starts another (to repeat a run, reload its rating or `?p=` link). The units are experimental; no calibrated meteorology is claimed.

**Layering (Options).** A radio group picks None, Inversion (cap) or LCL (flat bases, the default). Older presets with an `inversion` true/false still load as Inversion or None.

**Inversion.** Real cumulus rarely grow without limit. Over much of the ocean, air sinking in the subtropical highs warms as it is compressed, leaving a warm, dry layer over a cooler, moist mixed layer: the trade-wind or subsidence inversion. A rising parcel stays buoyant only while it is warmer than the air around it; at its level of neutral buoyancy, here the base of the warm layer, it stops and spreads sideways. That is why clouds pave out into flat sheets: stratocumulus decks under an inversion, cumulus whose tops flatten at the trade inversion, and thunderstorm anvils spreading under the tropopause, the stable layer at the top of the troposphere. Their flat bases are a separate effect: air everywhere condenses at about the same lifting condensation level. The model's version is the simplest one that does real work: at and above `inversionHeight` (default 0.6) the temperature relaxes at 0.02 per tick toward a fixed sounding, 0.4 at the base rising to 0.75 over 0.1 of the height and warm up to the lid. The cool base stands in for the cloud-top cooling that keeps a real capped layer overturning. Plumes arriving from below are colder than the layer, so they stall and spread into a flat-topped cloud layer just under it; the warm air above holds more vapor and stays clear. The cloudiest row moves from near the lid (off) to just under the inversion, and follows the height slider. Water is untouched, so it is still conserved. Inside the stable layer the air is quiet by design; the mixed layer below keeps overturning.

**LCL (flat bases).** Fair-weather cumulus have flat, sharp bottoms and lumpy tops. Under them is a well-mixed subcloud layer: turbulence gives it one moisture content and one potential temperature. A thermal rising out of it cools at the dry lapse rate (about 9.8 °C per km) while its dewpoint barely falls, so it saturates where temperature meets dewpoint: the lifting condensation level, about 125 m above the ground per °C of surface dewpoint spread. A thermal is only a fraction of a degree warmer than its surroundings, against a spread of several degrees, so every thermal reaches saturation within a few tens of metres of the others and the bases line up. Above the base, condensing vapor releases latent heat, the cloudy air stays warmer than its surroundings, and the tops keep billowing up. The model does the same with a few changes. Capacity is judged at each row's mean temperature, with a steeper lapse (`lclExpansion` 1), because the toy's plumes are far warmer than real thermals and would otherwise saturate above their surroundings. Vapor in the mixed layer, found by scanning up from the floor until the layer's mean vapor saturates, relaxes toward the layer's mean. The puddles hold floor vapor at the surface dewpoint, the vapor that saturates at `lclHeight` (default 0.35), giving water back as dew when the air is moister. Cloud also evaporates faster (`lclEvaporation` 0.3), so cloud below the base dries. The air mass is moister (`lclMoisture` 2 doubles the capacity), like the tropical trades, where cumulus hold enough water to rain; with drier air their rain all evaporates in the clear layer under the bases (virga). Water is only moved, so it is still conserved. The lowest cloud stays at about 0.37 to 0.40 with clear air under it, and moves up with `lclHeight`. In the Sunset view, cloud counts as a solid puff where it is rising as well as warm or capped, and the feathered fringe is cut back on a cloud's underside so the base stays crisp.

**Resolution (Options).** A toggle picks Pixel art 64 × 48 (the default) or Detailed 128 × 96. Switching restarts the run at the new size with the same seed and parameters, and turns `pixelArt` on for 64 × 48 and off for 128 × 96 (the checkbox can still override it). Lengths and speeds counted in pixels scale with `gridScale = width / 128`: the speed limit, rain fall, starting bubble radii, the Sunset view's blur, cap and underside reach, lobe and fray noise sizes, and the sun path and shadow strength. So both sizes behave as the same box with bigger or smaller pixels. Viscosity, diffusion and the per-tick rates are not rescaled, so the coarse grid is a little more damped: at 64 × 48 clouds tend to form big masses that hug the walls, and the Inversion's shallow convecting layer can settle on some seeds.

**Pixel art (`pixelArt`, drawing only).** The Sunset view's dusk sky is drawn as 3 flat bands per color step, ordered-dithered (a 4 × 4 Bayer matrix) over 35% of each band where they meet. Cloud light is stepped to 4 levels and its pink-to-peach tint to 3 (the warmth tint is off). The cloud core is solid above 0.5 cover, the feathered fringe becomes dithered solid pixels (cover over `0.2 + 0.6 × dither`), and rain becomes a dithered 50% curtain (rain opacity over `0.1 + 0.4 × dither`).

**Options** are plain run parameters (saved with each rating): `layering` (`none`, `inversion` or `lcl`) with `inversionHeight` (Inversion only) and `lclHeight` (LCL only); `cloudStyle`, Cumulus (the shaped cloud below) or Raw cloud water (the earlier smoky drawing of every bit of cloud by its own amount, shadowed toward the sun); `feather`, frayed cloud edges; `pixelArt`; and `resolution` (`64x48` or `128x96`). Only the layering and resolution change the simulation; the rest is drawing only. In LCL mode the `expansion` and `evaporation` sliders are greyed out, since it uses its own values.

The default Sunset view ties the fields together over a dusk sky. Drawn as-is, the advected cloud water looks like smoke (thin stretched streamers over a uniform upper deck), so the view draws solid cloud only where cloudy air is still buoyant, as cumulus are, or pressed under warmer air, as a stratocumulus layer is; blurs it so streamers fade and masses round off; and gives it a soft-thresholded, billowed edge and rounded shading from the shared sun's side (peach and pink lit while it is low, whiter when high, grey-violet in shadow; with no light given the model uses a low sun at the lower right). With `feather` on, a wider blur of the same field, frayed by fixed fractal noise, adds a translucent fringe that fades out over several pixels around the solid core. Still cloud and near-saturated air show as a faint veil, and rain as soft see-through curtains. The simulation itself is unchanged. The Lava lamp view shows buoyancy (warmer or cooler than the row average) with falling rain drawn in pale cyan; cloud and faint drizzle are left out so they cannot veil the blobs. Cloud and rain (gray-white cloud, pale cyan rain, blue vapor haze), temperature, buoyancy and relative humidity views isolate the fields with fixed color scales. Rule sliders affect the current run; `water` and New seed restart it. The emoji rating bar above the canvas (the shared [rating bar](../shared/README.md), app id `cloud-simulator/convection`) saves the rules, options, `water`, view and seed with a thumbnail on each tap. Its Recent list reloads anyone's rated settings, and Copy link puts the same settings in a `?p=` link that restores and restarts the run. Every experiment page has the same bar (core/host.js mounts it), with app ids `cloud-simulator/sunset`, `cloud-simulator/horizon`, `cloud-simulator/shafts`, `cloud-simulator/noise` and `cloud-simulator/valley`. Reduced-motion users start paused and background tabs do not accumulate catch-up. The shared service worker precaches the convection assets; installation opens the front page, which links to every experiment.

Model checks in `convection-model.test.js` cover water conservation and rain at both sizes, seed determinism, and sustained motion plus visible rain shafts over 4000 ticks on four pinned seeds (named in the test title; `FUZZ_SEEDS=1` draws fresh ones, `FUZZ_SEEDS=123,456` reruns listed ones): at 64 × 48, all four with the LCL and two with no layering; at 128 × 96, two with the inversion and one with the LCL. With the inversion on, motion is scored in the convecting layer under it. Further checks cover the old `inversion` boolean, the sounding, the cloud piling up under the inversion and following its height, the LCL's flat bases (at 64 × 48: the lowest base holds within 0.15 over time, under the inversion's cloud layer, with several times the share of columns lined up within 0.08 of it, and moving up with `lclHeight`; at 128 × 96: flat, at its height, lined up more than with no layering), and the capped (at both sizes), feathered and raw drawings. Browser review: watch blobs rise and fall and puffy clouds build and drift in Sunset for a minute, switch views, vary buoyancy and flicker, switch layering between None, Inversion and LCL and move their heights, switch cloud style, feathering, pixel art and resolution, check pause/step/Randomize/new seed, phone-width layout and offline reload.

## Horizon light: six layers and atmospheric color

Open [horizon.html](horizon.html). Three terrain silhouettes alternate with three cloud planes at fixed base distances 3/8/18/30/65/90 km. Cloud shapes are literal 32×12 grayscale bitmaps in `horizon-bitmaps.js`, generated once and stored as image data. No runtime noise/density evolution occurs. `horizon-model.js` owns scene geometry and rendering, `atmosphere-model.js` owns spherical-Earth extinction/scattering, and `horizon.js` owns controls/playback. All are precached in the existing app scope.

An Earth-sized sphere blocks direct sunlight by ray/sphere intersection. An exponential 8 km molecular scale height and 1.2 km aerosol scale height determine RGB optical depth to the top of the 100 km atmosphere. More blue leaves the direct beam than red. Each visible cloud pixel has its own altitude and sunlight path; distance changes the local horizon and camera-path extinction. A coarse 64×40 single-scattered sky is enlarged behind display-resolution cloud/terrain layers. Camera is at 150 m, fixed pitch 5° and vertical FOV 40°. Kilometers and degrees are used on controls; RGB radiance/exposure are relative.

Controls vary cloudAltitude, altitudeSpread (layer/instance offsets and bitmap thickness), distanceScale, atmospheric density, aerosols and exposure. The sun follows the shared vertical figure-eight path (`core/sun-path.js`, sized and placed by the `sunPath*` sliders); it remains infinitely distant and Play moves it around the path, starting paused. `horizon-experiment.js` describes the controls for `core/host.js`; old ratings and links with fixed `sunAzimuth`/`sunElevation` load at the nearest point on the path, and `sunSpeed` is ignored. A status summary reports cloud-center heights/distances and direct-light/shadow state. The canvas stays visible while controls scroll.

This is an independent CPU experiment inspired by [GPU Gems 2 atmospheric scattering](https://developer.nvidia.com/gpugems/gpugems2/part-ii-shading-lighting-and-shadows/chapter-16-accurate-atmospheric-scattering) and [Bruneton](https://ebruneton.github.io/precomputed_atmospheric_scattering/), not a port or calibrated implementation. Numerical sampling, RGB proxies, cloud/terrain shading, sky-based aerial perspective and ambient fill are explicit approximations. ## Experiment 04: noise weather

Open [noise.html](noise.html). A coarse 128 × 96 pixel-art slice where the noise only forces the weather: cloud water and rain are stored per pixel and evolve. `noise-model.js` owns the noise, the rules and the pixel colors; `noise-experiment.js` wraps it as an experiment module (sliders, view, Step, 20 ticks per clock second) and `noise.js` mounts it with `core/host.js`, which builds the controls, Drift and the rating bar. Its Sunset view is lit by the shared sun (`core/sun-light.js`), so the page has the Sun group; it keeps playing when a saved look loads. This tries a cheaper route to endless motion than the convection study: instead of physics that has to be tuned to keep moving, the weather fields are 2D slices of seeded 3D Perlin noise whose third axis is time, so they drift smoothly forever.

Twelve sliders in three groups. **Sky:** `cloudiness` (mean humidity), `featureSize` (cloud clump size in pixels), `texture` (smooth to ragged: one knob for the fractal octaves, 1 to 6, and roughness, 0.3 to 0.75, of humidity and temperature; the default 0.65 gives the frayed, grainy cloud edges of the first rounds), `changeSpeed` (how fast the noise moves through time; 0 freezes the shapes) and `wind` (one global signed wind in pixels per tick; negative blows left). `humidity`, `temperature` and `pressure` are each a noise slice; their amplitudes, and pressure's octaves, are fixed in `noise-model.js`, and temperature and pressure use larger, slower features so the three do not line up. The wind scrolls all three sideways together, so clouds drift across as objects, and carries all stored cloud water, charge and rain the same way (cloud water and charge in whole pixels, so they never blur and stay within half a pixel of the noise; rain sub-pixel). Capacity is `exp(3 × (temperature − 1)) × (1 + 0.3 × pressure)`; relative humidity is humidity over capacity.

**Cloud layer:** clouds form only inside a band of height. `band(altitude) = exp(−(|altitude − layerHeight| / w)^1.5)`, where the half-width `w` is `layerThickness / 2 × (1 + layerAsymmetry)` above the middle and `× (1 − layerAsymmetry)` below. It is 1 at `layerHeight` and fades softly to about 0 above and below (the fixed exponent 1.5 is softer than a Gaussian: no flat top or hard edge; there is no sharpness setting, and an old saved `layerSharpness` is ignored), and positive asymmetry gives a flatter bottom and a taller soft top (the default). The noise's cloud potential is `clamp((relative × band − 1) × 8)`. At the defaults the potential reads as one horizontal layer with clear sky above and below on any seed. `persistence` (in this group) sets how long cloud outlives its forcing.

**Cloud water:** each pixel stores cloud water. Where the potential is higher it condenses fast (30% of the gap per tick); where it is lower it evaporates slowly and from the edges in: `0.04 × 10^(−1.5 × persistence) × (0.05 + 10 × exposure)` per tick, where `exposure` is the mean cloud missing from a pixel's 8 neighbors (sides wrap; the lid and floor do not count as edges). Deep inside a cloud exposure is 0 and it barely thins; on a straight edge it is about 0.4 and on a lone pixel 1, so a fading cloud keeps a dense core and shrinks as its edge eats inward. So clouds pop in quickly with the noise but linger after the noise has moved on.

**Rain:** only dense cloud water (at least 0.8) that stays dense charges up (+0.012 per tick; anywhere thinner the charge drains 10% per tick). Past 0.6, about 50 ticks of staying dense, it makes up to `rainAmount` rain per tick, more the denser it is, and loses twice that in cloud water. So rain starts only in intense, lasting cores, never at a cloud's thin outskirts; a cloud the noise still feeds keeps raining, and one it has stopped feeding rains itself thin, stops raining while still visible, and then fades. Rain is the one real dynamic field: every tick all of it moves `fallSpeed` pixels down and `wind` pixels sideways (split over neighboring pixels so it glides), loses 1.5% per tick outside cloud while cloud is still overhead and 10% once no cloud is left above it in its column (so rain from a dissolved cloud does not hang in clear sky), and collects in floor puddles that slowly dry. Rain made equals rain in the air plus puddles plus evaporated, exactly; the noise fields carry no water budget.

The default Sunset view draws nine dithered sky bands, cloud in four shades lit toward the shared sun (each cloud pixel compares itself with the cloud one step toward the light; the palettes move toward daylight under a high sun), and rain as a separate display-only layer that starts inside the cloud. Under each column with a raining dense core, a curtain smooths the cloud's lower part from the top of that core (at most 6 pixels above the base) and stretches below the base: it grows down at `fallSpeed` while the column rains (up to 26 pixels), fades to nothing at its foot, is blurred across neighboring columns and dithered, and thins away once the core stops raining (fast once no cloud is left). So a raining cloud keeps a fluffy top while its base turns into a smooth sheet falling out of it, with no gap. On top of it, thin streaks are born inside the cloud, anywhere from the top of the raining core to just under the base, in a column with a raining dense core, at random sub-pixel positions and random ticks, likelier where rain is heavier and where a slow wind-carried clumping noise is high, so they gather into uneven shafts. Lengths are heavy-tailed, 3 to 30 pixels (mostly short, a few long); each streak gets its own speed (±20% of `fallSpeed`), strength and sometimes a second pixel of width. Streaks lean and drift with the wind, never reach above the row they were born on (so they grow out of the cloud), fade in and out over their life and toward both ends, and fade out within a few ticks once no cloud is left above them. They are drawn as sky-tinted grey, antialiased across neighboring columns. Cloud and rain (stored cloud water, gold where it rains), cloud forcing (relative humidity × band), humidity, temperature and pressure views isolate each field. Every slider affects the current run; while paused, a slider change also resets the stored cloud to the new forcing so it shows at once. Playback runs at 20 ticks per second. The emoji rating bar above the canvas (the shared [rating bar](../shared/README.md), app id `cloud-simulator/noise`) saves every slider, the view and the seed with a thumbnail on each tap; Recent and `?p=` links restore them and restart the run. The page picks a random seed; New seed starts another (to repeat a run, reload its rating or `?p=` link). Reduced-motion users start paused.

Run `node --test apps/cloud-simulator/*test.js`; the noise, convection and lightning tests use pinned seeds (`FUZZ_SEEDS=1` for fresh ones). Browser review: watch clouds form, rain and fade in Sunset for a minute, switch views, drag each slider (change speed 0 freezes the shapes; wind 0 stops the drift), check pause/step/Randomize/new seed, phone-width layout and offline reload.

## Experiment 04: cloud light strategies

[shafts.html](shafts.html) offers Visibility polygons, Layered visibility polygons (default) and Geometric shadows. The geometric strategy uses three fixed cloud pictures (32×20, 64×40, 96×60) at depths 22/50/78. Each opaque cloud cell extrudes a rectangular shadow prism away from the sun across the gaps between layers. Projected prism bounds bin candidate shapes into two 64×40 screen buffers. Camera rays intersect those prisms analytically, merge overlapping shadow intervals, and integrate exponentially attenuated haze over the remaining illuminated intervals. Each buffer therefore represents its gap's full depth, not one flat midpoint. No volume grid, stack of slices or depth ray march is used.

`shafts-model.js` owns geometry, interval unions and image composition; `shafts-experiment.js` describes the controls for `core/host.js`, which owns playback and the emoji rating bar (app `cloud-simulator/shafts`). Camera perspective stays fixed at 58°. Simulation/controls retain separate panes. Fields grow in world coverage with distance. Opacity times contrast-adjusted density ≥0.5 makes an opaque air-shadow silhouette. cloudSharpness adjusts contrast around 0.35. Shadows always use one camera ray per pixel for crisp edges, with nearest-cell sampling for cloud-surface shadow lookup. Surface cloud shading retains soft density and partial transmission; this deliberate hybrid is not a physically complete atmosphere. Sky, solar RGB, tone mapping, and attenuation by depth rather than exact camera path length are approximations. No multiple scattering or foreground haze ahead of the nearest sheet.

The sun follows the shared vertical figure-eight path (`core/sun-path.js`); the scene follows its full elevation range: below the horizon the sun disc is hidden and the shafts fade out smoothly by about −4.6°, and a high sun sits above the view and casts short, downward shafts. Across, the sun follows the path's whole swing (up to ±90°): past about ±41° it is off-screen and its shafts slant in from that side; beyond ±60° it eases toward ±80° so the shadows stay finite. (`softAzimuth` in `shafts-experiment.js`) Sliders control cloudOpacity, haze, cloudSharpness and, for the visibility strategies, sourceRadius and edgeFeather. The New nearPattern, New middlePattern and New farPattern buttons (named for their keys, like New seed) increment one layer's seed; Randomize picks new patterns, a strategy, the light sliders and the time of day. Old links with fixed `sunAzimuth`/`sunElevation` load at the nearest point on the path. Haze=0 removes air light; cloudOpacity=0 removes clouds and their shadows. Formulas are in the collapsed on-page explanation.

Run `node --test apps/cloud-simulator/*test.js`. Review geometric wedge boundaries while moving the sun, sharpness, independent pattern changes, Randomize, phone scrolling and offline navigation after worker activation. Browser checks remain separate from model/GUI harness evidence.

### Visibility polygon strategy

Experiment 04 defaults to Layered visibility polygons, with a radio switch back to the existing Geometric shadows. The switch shares all current fields and controls; Randomize picks a strategy too. `visibility-model.js` thresholds the cloud fields, extracts and merges collinear silhouette boundary segments, projects them and the sun into screen space, and casts rays at endpoints and small angular offsets to form one visibility polygon per layer. Pixel masks intersect those polygons for each group of cloud layers.

Visibility composition now draws every light veil before a separate cloud-body pass: back-to-front sun → far light → middle/far light → all-three light → far cloud → middle cloud → near cloud. Thus even the far cloud covers nearer light veils, with partial transmission still letting light through. Veil opacity is reduced to 55% of the previous haze mapping, is applied only in lit regions, and cloud bodies have neutral-blue shadow fill plus a warm lit contribution. This protects their visible structure. This is a screen-space point-light approximation: sourceRadius (default 6 native image pixels) makes nearby cloud edges transparent to sunlight. Rays escape if the cloud ends within the radius; cloud matter beyond it still blocks them. Radius 0 restores hard blocking; it is disabled in geometric mode. Circle/segment clipping preserves distant portions of crossing edges, and rays check solidity just beyond the pass-through zone. Hard silhouette occlusion, finite expanded polygon bounds, coarse cell edges and soft cloud-surface shading remain deliberate approximations. It does not calculate 3D shadow depth. The previous geometric mode is retained unchanged.

Conceptual reference: [Red Blob Games, 2D Visibility](https://www.redblobgames.com/articles/visibility/). Our endpoint-ray implementation is independent; there is no added dependency. New source module is included in the existing worker’s precache. Review strategy switching, identical pattern seeds, sun movement and Randomize in both modes, then browser/mobile and offline behavior separately.

### Layered visibility bands

The third radio option builds three independent sets of per-cloud visibility polygons over the same fields. Bright/middle/soft thresholds are 1.0/0.5/0.25; their source radii are 1.8/1.0/0.6 times sourceRadius; translucent opacity weights are 0.25/0.35/0.4 and brightness scales 1.2/1.0/0.8. Higher threshold and radius let the bright band penetrate thicker clouds. These fixed presets avoid adding a bank of sliders. The new mode and the single-band mode share the cloud-protecting two-pass composition. Geometric shadows remain unchanged. Three polygon passes cost more than one; timing is displayed and phone performance remains unmeasured.

### Selective visibility-edge feathering

edgeFeather defaults to 4 native image pixels (0–6), applies to both visibility strategies, and is disabled in geometric mode. Polygon edges aligned radially away from the sun are shaft sides and stay hard. Other visible boundaries are cloud/radius caps; distance to those segments produces an inward smoothstep alpha ramp. Coverage remains zero outside the original polygon, so this is not a blur of the full mask. Cloud fields and polygon geometry are unchanged. Layer-group coverage multiplies the per-layer ramps for both air veils and surface lighting; opaque cloud bodies still compose above all veils.

Play sun animates both azimuth and elevation from the current values. sunSpeed defaults to 3 azimuth degrees/second (0.25–15); elevation moves at 40% of that rate. Both bounce at their slider limits, stop while paused/hidden and do not accumulate background catch-up. Editing either angle pauses playback. (Superseded: the page's Reset is now Randomize, which picks the strategy and patterns too.) The page initially selects Layered visibility polygons and starts paused.

## Valley textures: photo regions and varied brushes

[valley.html](valley.html) offers eight sourced CC0 cloud bitmaps, with grayscale/alpha previews, two selectors and one blend slider. Source/license/crop details and hashes are in [textures/README.md](textures/README.md). Photo sources decode into grayscale shading plus approximate sky-removal alpha; source RGB is discarded. Six original brush maps use intensity as opacity. Fine cloud detail comes from the bitmaps, not runtime noise.

`valley-model.js` owns reveal/terrain/rendering, `valley-sampling.js` owns photo crops and varied brush placement, `valley-textures.js` owns decoding/matting, `valley-experiment.js` wraps them as an experiment module (texture loading behind its `ready` promise, the previews through `decorate`, the wind clock, which the common Play and Step drive; Step moves it one second) and `valley.js` mounts it with `core/host.js`, which builds the controls and adds the emoji rating bar (app id `cloud-simulator/valley`). Ratings save every control but not the wind clock. The shared sun lights it (`core/sun-light.js`): its glow sits where the sun is (45° of azimuth to each edge, the horizon at the valley floor's eye level, 50° up per picture height) and sinks behind the hills at dusk, slopes facing its side are lit, and clouds near it get a silver lining and dim as it sets; the page has the Sun group. The display is 192×120 with independent control scrolling. Step pauses and advances one second; New seed steps to the next brush layout (its key is `seed`, like every page's New seed; links saved with the old name `brushSeed` still load); Randomize picks every slider, the texture pair, the horizon, the brush layout and the time of day. Assets are precached in the scope-isolated worker. Run `node --test apps/cloud-simulator/valley*.test.js`; actual browser/offline/mobile verification is reported separately.

Valley textures also includes two real CC0 sunset-photo crops (runtime grayscale shading and soft sky-removal alpha; source RGB is discarded), horizon radios (deep valley/low hills/open), and full-sky/high/low/separated-height placement. The default reveal multiplies two independently seeded 3D Perlin fields, sampled on 33×21 grids with time as their third dimension and opposing horizontal drift. Noise scale, drift, formation speed, coverage and softness are adjustable. Legacy masks/maps remain available; see textures/README.md for photo authors, crop details and licenses.

`windwardClearance` and `leewardClearance` control cloud-free depth along opposing sides of the visible hillside (normalized image-height units). Signed wind and the broad hillside slope (ignoring decorative ridge ripples) select which applies; reversing wind swaps sides. Every cloud layer uses the same visible envelope, and terrain renders last, preventing hidden ridges from punching detached holes. The clearance increases smoothly from terrain toward the sky without noise pockets. Flats, peaks and calm wind add no clearance. Set one side to zero for clouds to hug that slope. This is an artistic slope mask, not airflow simulation.

Cloud A/B selectors replace the bitmap radios, with grayscale/alpha checkerboard previews. Each offers eight bitmaps: six unchanged CC0 pack maps plus two photograph-derived masks. A single `textureBlend` slider transitions 0=A to 1=B. Samples use shared wind and reveal fields; alpha and alpha-weighted grayscale shading mix before lighting, so transparent texels cannot darken the transition. Selection/blend changes retain clock and other parameters. Reloading the page restores Sculpted bank / Billowy bank, blend 0. No automatic blend playback is added. Texture decoding remains in `valley-textures.js`; approximate photo mattes are documented beside source provenance.

### Photo regions versus brush stamps

`valley-sampling.js` separates two sampling strategies. Photograph-derived masks occupy one back sky plane as an aspect-preserving wrapping sky strip. `textureScale` controls photo zoom (minimum 1), while wind continuously advects the strip at the same rate as back-layer brushes, even at zoom 1. At load, an 18% left/right overlap blends scalar alpha and premultiplied grayscale shading to make the original crop wrap smoothly. Wrapped bilinear sampling interpolates across the seam in both wind directions. There is no mirroring or duplicated photo on the other two planes. The whole pattern eventually repeats after one strip period; the source files are unchanged.

Brush maps use stable world-grid stamps with seeded position jitter, independent width/height, horizontal/vertical flips, small rotations and opacity variation. Wind advects the same stamps; variation is not regenerated per frame. Stamps rasterize to scalar opacity and premultiplied grayscale fields once per layer. Texture edges are transparent, never repeated texel coordinates. New seed advances the layout seed without changing time, photos or sliders. A fresh page load starts at seed 1. Both A/B samplers feed the existing opacity-weighted blend and reveal/lighting pipeline. Original image aspect is retained during load.

## Next round: Lightning and a shared scene contract

[lightning.html](lightning.html) is the first architecture-driven study under #69. Three ordered depths each own clouds, a 12×6 signed charge field, branching channels and terrain. Slow stochastic buildup, relaxation and diffusion create regional gradients; crossing `breakdownGradient` triggers a cloud-to-cloud or cloud-to-ground channel. A completed connection discharges its layer and flashes. Only ground strikes illuminate a local patch of their own terrain; fixed trees and rocks cast long contact-light shadows, and foreground hills occlude farther light. Ten sliders control field evolution, channel growth and illumination. Next shape prepares one naturally triggered event on a new seed, paused at peak; Before strike prepares one paused before growth. These two stay Lightning's own buttons. The other layers retain independent charge. Numeric seeds stay internal. Lightning runs on the shared core (`lightning-experiment.js` wraps the unchanged scene and its fixed-step session), so it has the common panel: Play, Step (one 1/60 s scene step), Randomize, Drift and New seed (a fresh strike in the current starting mode). Its old Reset (default sliders, same seed) is replaced by Randomize. Ratings and links saved by its earlier host (`{version: 1, seed, params, start}`) still load. This is a stylized potential-field model, not an electrical solver.

[experiment-architecture.md](experiment-architecture.md) defines the scene/session contract: pure model module, JSON state, read-only pixel renderer, canonical parameter schema and a fixed-step session; `lightning-experiment.js` adapts it to the shared core host. Model/session/page checks: `node --test apps/cloud-simulator/lightning*.test.js apps/cloud-simulator/experiment-*.test.js`. Browser, phone and offline verification must be reported separately.

Lightning timing is charge-driven: quiet → leader → flash → quiet. Each quiet layer advances its own coarse charge field, then compares the strongest cloud/cloud or cloud/ground potential difference per distance against `breakdownGradient`. `chargeRate` controls field evolution, with zero freezing quiet potential values. `chargeBias` adds a signed mean to charge buildup (default +0.2; zero is unbiased). Either sign can favor ground connections by increasing the cloud/neutral-ground difference; it does not force a strike type. Bias is multiplied by `chargeRate`, so zero rate still freezes potentials. `fieldBias` steers the leader toward the selected sink. Contact reduces field values and drift, and `flashDuration` controls the flash decay. There is no periodic `interval` or forced shared strike time. Setup preparation advances charge privately until one event is ready; it uses unit buildup if `chargeRate=0` so the inspection controls still produce a shape. Presets retain seed, parameters and starting mode, not an exact live frame. Old presets normalize against the current schema; geometry/timing can change as the experiment evolves.
